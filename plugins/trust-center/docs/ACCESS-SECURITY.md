# Document access security and remaining work

The public API returns only explicitly public documents. Private document details and downloads require a Cognito-authorized `/api/private/documents/...` route and an approval bound to the caller's Cognito subject and document; admins can also access private documents. Requests must be submitted to that private route using an authenticated identity. Legacy approvals without `requesterSub` do not grant access and require a new request or a verified migration.

This is backend groundwork, not a complete user-facing access flow. The current frontend still uses public request/download routes and does not implement the private requester sign-in and approval flow. Existing presigned links remain valid until their one-hour expiry, including after revocation or a public-to-private change. Previously disclosed objects and metadata cannot be recalled. An approval does not enforce NDA signing.

The handler trusts API Gateway authorizer claims on private/admin paths. Never expose the Lambda through an unauthenticated function URL or permit untrusted direct invocation. API Gateway routing, Cognito token/claim behavior, CloudFront caching and forwarding, S3 bucket isolation, permissions, deployment replacement, CORS, and end-to-end access have not been validated in AWS. CloudFormation API Gateway deployments may need replacement on updates; verify the deployed stage includes all methods. The reference infrastructure differs from the main template, including its existing authenticated public proxy; validate it independently before use. Do not deploy without resolving these items and reviewing the complete security configuration.
